   Desbordamiento horizontal en tablas tarifas.html:
Problema: En pantallas de 360 px, las tablas de tarifas y recorridos se salian de la pantalla por el tamano de fuente y los margenes fijos.
Solucion: Se redujo el tamano de texto y el espaciado en la version movil (table, th, td), logrando que se lean completas sin scroll lateral.
Apilamiento del menu de navegacion (header):
Problema: El logo y los enlaces del menu se amontonaban horizontalmente en celulares, rompiendo el diseno.
Solucion: Se ajusto con flex-direction: column para que el nombre quede arriba y el menu centrado abajo en movil, recuperando la distribucion horizontal original a partir de 768 px.
Imagenes rebasando contenedores:
Problema: Algunas imagenes de la flota y las rutas conservaban su tamano original y descuadraban la vista vertical.
Solucion: Se aplico una regla global con max-width: 100% y height: auto para asegurar que todas las imagenes se adapten de forma fluida a cualquier pantalla.


Tiempo invertido: ~10 minutos construyendo la vista con Bootstrap frente al diseño hecho a mano en CSS nativo.
Lineas de codigo de distribucion:
Version CSS propio: Mas de 25 lineas combinando flexbox, media queries (min-width: 768px / 1200px) y selectores de grilla personalizados.
Version Bootstrap 5: Cero lineas de CSS propio; toda la logica de columnas se resolvio unicamente empleando clases utilitarias del framework (row, g-3, col-12, col-sm-6, col-lg-4, col-xl-3).

Semana 3 Dia 1
Comparativa de Botón (Bootstrap vs. Tailwind CSS)
En la semana 2 usé Bootstrap para el botón con clases predefinidas como btn btn-primary,
 donde la librería maneja los estilos por defecto.
  Hoy con Tailwind usé clases de utilidad atómicas directamente en la etiqueta (inline-block bg-emerald-500 text-slate-950 font-bold px-6 py-3 rounded-xl uppercase tracking-wider text-sm), lo que me dio control total de diseño en el HTML.
Diferencia clave: Bootstrap es un framework de componentes con estilos listos y rígidos.
 Tailwind es utility-first, ofreciendo utilidades de bajo nivel para construir cualquier diseño desde cero sin salir del HTML ni escribir CSS custom.


 Tailwind CLI y optimización de clases

Al revisar el archivo generado src/output.css tras compilar con la CLI, comprobé que las clases utilizadas en el HTML (como bg-emerald-500 o text-white) se compilan e incluyen en el archivo final.
 Por el contrario, clases que no utilicé en el código (como bg-pink-500) no aparecen por ninguna parte.
  Esto ocurre porque el motor de Tailwind analiza los archivos fuente de manera estricta para generar únicamente el CSS necesario, manteniendo el archivo ligero y optimizado para producción.


  
  Estandarización del Kit de Componentes
Bordes y formas: Se unificó el uso de rounded-2xl para tarjetas y contenedores principales, y rounded-xl para elementos internos como botones, inputs y alertas, logrando una línea visual coherente.
Espaciado: Se utilizaron rellenos consistentes (p-6 en contenedores y p-4 en componentes secundarios) junto con separaciones verticales (space-y-4) para mantener orden y jerarquía.
Colores: Se mantuvo la paleta base de tonos slate para el fondo y tarjetas, destacando las acciones principales con verde esmeralda (emerald-500) y usando colores de apoyo (ámbar y celeste) para diferenciar las alertas.
